# Світло вдома — ТОЕ

Новий React застосунок замість старого HTML віджета. Старий парсинг новин і `api.toe.com.ua` повністю видалено. Використовується лише `api-poweron.toe.com.ua`.

## Запуск

Потрібен Node.js 22.12+.

```sh
npm ci
npm run dev -- --port 4173
```

Для звичайного запуску з production збіркою:

```sh
npm run build
npm start
```

Відкрити http://localhost:4173. `PORT` змінює порт, `HOST` — інтерфейс прослуховування (типово `127.0.0.1`). Для доступу з Home Assistant або іншого пристрою сервер має бути доступний у вашій мережі. Для HTTPS Home Assistant застосунок також потрібно віддавати через HTTPS.

Проксі `/toe-api` необхідний через обмеження браузерних запитів до ТОЕ. Production сервер `server.mjs` дозволяє лише читання п'яти потрібних ендпоінтів, не пересилає cookies або авторизацію браузера та має таймаут. Самих статичних файлів у `/config/www` недостатньо для проксі. Дані адреси надсилаються лише API ТОЕ.

## Можливості

- На головному екрані: сьогодні / завтра, усі черги для адреси, 24 годинні блоки з півгодинними станами.
- Окремий екран налаштувань: місто → вулиця → точна назва будинку → автоматичне визначення черг.
- Адреса й параметри сповіщень зберігаються в localStorage браузера.
- Оновлення кожні 5 хвилин, ручне оновлення, повідомлення про помилки та відсутність опублікованого графіка.
- Білий — подача, фіолетовий — відключення, сірий — перемикання, штрихування — немає даних. Відсутні слоти не означають наявність світла.
- Час графіка — Europe/Kyiv; дата створення показана так, як її надає ТОЕ.

## Home Assistant

Застосунок з проксі має працювати на сервері. Підключіть його стандартною webpage/iframe карткою або власною обгорткою `public/toe-power-card.js`:

1. Скопіюйте `public/toe-power-card.js` у `/config/www/toe-power-card.js`.
2. Додайте `/local/toe-power-card.js` як ресурс JavaScript Module у панелі.
3. Додайте картку:

```yaml
type: custom:toe-power-card
url: https://YOUR_TOE_APP_HOST/
height: 950
```

Це заміна попередньої картки: параметри `group` та `address_key` тепер вибираються в налаштуваннях самого застосунку. Сенсори Home Assistant не створюються.

## Ранкові повідомлення

На екрані налаштувань увімкніть «Ранковий графік», оберіть час (типово **09:00**) та дію доставки. `persistent_notification.create` показує повідомлення всередині HA; для телефону вкажіть вашу дію `notify.mobile_app_...`.

Натисніть «Завантажити налаштування HA». Завантажений пакет містить точну адресу, усі визначені черги, вибраний час та стан увімкнення. Для встановлення:

1. У `configuration.yaml` додайте до розділу `homeassistant` (не створюйте повторний розділ):

   ```yaml
   homeassistant:
     packages: !include_dir_named packages
   ```

2. Збережіть завантажений файл як `/config/packages/toe_morning.yaml`, замінивши попередній пакет.
3. Перевірте, що часовий пояс HA — `Europe/Kyiv`.
4. Перевірте конфігурацію та перезапустіть Home Assistant; вручну запустіть автоматизацію для перевірки доставки.

Перемикач у застосунку змінює завантажуваний пакет; він **не керує підключеним Home Assistant напряму**. Після зміни налаштувань повторно завантажте та встановіть пакет. Сповіщення працюють із закритим браузером завдяки Home Assistant, який має працювати з інтернетом о заданій годині. Пропущений запуск не надолужується.

Файл `home-assistant/toe_morning.yaml` — шаблон із заповнювачами. Завантажуйте готовий пакет із налаштувань після вибору власної адреси. Фактичну доставку в HA ще не перевірено.

## API

База: `https://api-poweron.toe.com.ua/api`.

| Ендпоінт | Призначення |
|---|---|
| `/pw_cities?pagination=false&otg.id=` | Міста |
| `/pw_streets?pagination=false&city.id=CITY_ID` | Вулиці |
| `/pw-accounts/building-names?cityId=CITY_ID&streetId=STREET_ID` | Точні назви будинків |
| `/pw-accounts/building-groups?cityId=CITY_ID&streetId=STREET_ID&buildingNames=BUILDING_NAME` | Черги адреси |
| `/a_gpv_g?before=...&after=...&group[]=2.2&time=...` | Графік |

`time` — адреса `cityId/streetId/buildingName` без `/`, не часовий штамп. `X-debug-key` — Base64 UTF-8 адреси зі слешами. Графік: `dataJson[group].times["HH:mm"]`; `0` — подача, `1` — відключення, `10` — перемикання. `cdn-cgi/rum` — телеметрія, не використовується.

Іконки станів взято з офіційного сайту ТОЕ. API неофіційно досліджено за клієнтським кодом та живими відповідями; формат може змінюватися.

## Перевірка

```sh
npm test
npm run build
```

Автоматичні перевірки покривають київську дату, запит кількох черг, UTF-8 адресу, відсутні слоти та об'єднання інтервалів до 24:00. Інтерфейс перевірено у браузері з локальним аналогом Ingress. Сервер `npm start` — підтримуваний спосіб production запуску; допоміжні файли Sites зі стартера не замінюють його проксі.

## Встановлення як застосунку Home Assistant OS

Репозиторій уже містить `repository.yaml` і самодостатній add-on `toe/`. Підтримуються **amd64** та **aarch64**. Supervisor збирає контейнер локально з `toe/Dockerfile`, без окремого контейнерного реєстру.

1. Створіть GitHub-репозиторій і завантажте весь проєкт разом із **згенерованою папкою `toe/app`**. Git remote у цьому workspace поки не налаштовано; проєкт ще не опубліковано.
2. У Home Assistant OS відкрийте **Налаштування → Застосунки → Магазин → ⋮ → Репозиторії** та додайте URL свого Git-репозиторію.
3. Знайдіть «Світло вдома — ТОЕ», установіть і запустіть. Перша збірка потребує інтернету.
4. Увімкніть показ у бічній панелі та відкрийте вебінтерфейс. Окрема Lovelace картка й адреса сервера не потрібні.
5. Виберіть адресу на екрані «Налаштування».

Інтерфейс відкривається через Ingress: автентифікацію виконує Home Assistant, порт на хості не публікується. Add-on не має Supervisor API доступу, host network, доступу до конфігураційних файлів HA або привілейованого режиму. Локальні налаштування залишаються окремими для кожного браузера. Сповіщення в 1.0.0 ще потребують встановлення експортованого YAML, як описано вище; автоматичного керування HA API немає.

### Випуск оновлення

Після зміни коду:

```sh
npm ci
npm run addon:prepare
npm test
```

Збільште `version` у `toe/config.yaml`, додайте опис у `toe/CHANGELOG.md` та завантажте зміни, **включно з `toe/app`**, у той самий Git-репозиторій. У HA оновіть інформацію магазину й натисніть «Оновити» для застосунку. Supervisor сам перебудує контейнер. Зміна коду без зміни версії не створює пропозицію оновлення.

Для локального встановлення без GitHub можна скопіювати вміст `toe/` у `/addons/toe/` через наявний файловий доступ до HA, оновити магазин та встановити застосунок із розділу локальних. Це ручне встановлення; оновлення також копіюються вручну.

Пакування, тести та локальний запуск перевірено; установлення в реальному Supervisor і збірка Docker потребують доступного Home Assistant OS / Docker daemon.

Офіційні вимоги: [Ingress](https://contributors.home-assistant.io/apps/guides/ingress/), [репозиторії застосунків](https://contributors.home-assistant.io/apps/guides/repository/).

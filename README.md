# Світло вдома — ТОЕ

Home Assistant app for Ternopiloblenergo power outage schedules, with a shared household address and personal mobile notifications.

## Встановлення у Home Assistant OS

1. **Налаштування → Застосунки → Магазин → ⋮ → Репозиторії**.
2. Додайте `https://github.com/Maksym5248/ha-toe-power`.
3. Установіть «Світло вдома — ТОЕ», запустіть і ввімкніть показ у бічному меню.
4. Відкрийте вебінтерфейс через Ingress. Адміністратор один раз задає адресу дому.

Підтримуються **amd64** та **aarch64**. Supervisor збирає контейнер локально. Порт на хості не відкривається. Кожен користувач повинен входити зі **свого облікового запису Home Assistant**; спільний обліковий запис означає спільні особисті налаштування.

## Тема Home Assistant

Через Ingress інтерфейс підхоплює активну тему HA: кольори фону, карток, тексту, полів, акценту та основний шрифт. Зміна теми застосовується без перезавантаження. Кольори станів графіка залишаються стабільними відповідно до легенди. Поза HA або у iframe з іншого origin використовується системна світла / темна тема.

## Спільний графік, особисті сповіщення

- **Адреса дому** зберігається на сервері та однакова для всіх. Змінювати її можуть лише адміністратори HA; права перевіряє сервер.
- Місто, вулиця й будинок вибираються з пошуком; черги визначаються автоматично.
- На головному екрані — графік сьогодні / завтра з півгодинними станами. Оновлюється кожні 5 хвилин.
- **Мої сповіщення** прив'язані до облікового запису HA та одного підтвердженого телефона. Керувати ними можна з будь-якого браузера після входу під своїм користувачем.

У «Моїх сповіщеннях» виберіть телефон, отримайте одноразовий код і підтвердьте його. Потрібен Home Assistant Companion із дозволеними push-сповіщеннями й зареєстрованою дією `notify.mobile_app_...`. Телефони не визначаються автоматично за браузером. Вибір із підтвердженням допомагає не підписати чужий телефон.

Після підтвердження доступні три незалежні опції:

| Опція | Коли надсилається |
|---|---|
| Ранковий графік | У вибраний час, типово 09:00, якщо є відключення / перемикання або графік недоступний |
| Перед відключенням | Приблизно за 30 хв до початку планового відключення або можливого відключення / перемикання |
| Перед відновленням | Приблизно за 30 хв до очікуваного відновлення за графіком |

Натисніть **«Зберегти сповіщення»**. Кнопка **«Надіслати тест»** перевіряє доставку. YAML, автоматизації та ручне копіювання файлів більше не потрібні. Налаштування інших користувачів не змінюються. Повторне підтвердження того самого телефона іншим обліковим записом переносить його підписку, щоб уникнути подвійного надсилання.

Адреса та підписки зберігаються в `/data/toe/subscriptions.json`, переживають перезапуск і входять у дані add-on для резервного копіювання. Зміна адреси дому автоматично застосовується до повідомлень усіх підписників.

## Що важливо знати

- Усі часи — **Europe/Kyiv**. Сповіщення працюють із закритим браузером, але потрібні запущені add-on / Home Assistant та інтернет.
- Графік не вимірює фактичну наявність електрики. Відновлення завжди позначається як очікуване.
- Відключення й суміжні періоди перемикання розглядаються як один період можливої відсутності світла. Відновлення — перший відомий інтервал подачі після нього. Пропущені слоти не означають наявність світла.
- Сервер перевіряє графік для нагадувань щохвилини та планувальник кожні 30 секунд. Пізно опублікований графік може дати нагадування менш ніж за 30 хвилин; повідомлення містить актуальний час до події. Після початку події застаріле нагадування не надсилається.
- Збережені відмітки запобігають повторній відправці при звичайному перезапуску. Якщо мережевий запит завершився невизначено після прийняття повідомлення HA, повторна спроба може його продублювати.
- Ранковий запуск може надолужити до однієї години після вибраного часу. Нагадування про скасовані події не плануються за старим кешем після наступного успішного оновлення. Уже доставлене повідомлення не відкликається.
- При переході на літній/зимовий час графік містить локальні півгодини без позначення повторної години; одна й та сама локальна подія не дублюється.

## Доступ до Home Assistant

Версія 1.1.0 потребує `homeassistant_api: true` для переліку телефонів, перевірки адміністратора і надсилання сповіщень. Supervisor передає токен лише серверу; у браузер він не потрапляє. Цей дозвіл дає add-on адміністративний доступ до Core API — власний HTTP API застосунку обмежений спільною адресою та особистими підписками.

Сервер в add-on приймає з'єднання лише від Ingress Supervisor `172.30.32.2`, використовує підтверджений ним `X-Remote-User-Id` та відмовляє, якщо користувача немає. Немає host network, доступу до файлової конфігурації HA або привілейованого режиму. Коди діють 5 хвилин, мають обмеження спроб і частоти; у браузер / журнали код не повертається.

Якщо раніше встановили YAML-автоматизацію версії 1.0.0, вимкніть її, щоб не отримувати дублікати. Сам add-on не змінює ваші старі автоматизації.

## Розробка та випуск

Потрібен Node.js 22.12+:

```sh
npm ci
npm run addon:prepare
npm test
npm start
```

Локальний standalone запуск: http://localhost:4173. Пошук адреси й графік доступні; підключення персональних сповіщень потребує реального HA Ingress. Для Vite frontend: `npm run dev`, із проксі `/toe-api` на ТОЕ та `/app-api` на локальний Node server.

Для випуску збільште `version` у `toe/config.yaml`, оновіть `toe/CHANGELOG.md`, виконайте `npm run addon:prepare` і `npm test`. Завантажте зміни в Git **разом із згенерованою папкою `toe/app`**. У HA оновіть інформацію магазину й установіть нову версію. Перезапуск сам по собі код не оновлює.

Встановлення через Ingress не потребує окремої Lovelace картки. `public/toe-power-card.js` залишено для окремого зовнішнього розміщення вебзастосунку.

## API ТОЕ та перевірки

Застосунок використовує лише `api-poweron.toe.com.ua`: `pw_cities`, `pw_streets`, `pw-accounts/building-names`, `pw-accounts/building-groups`, `a_gpv_g`. Телеметрія `cdn-cgi/rum` і старий парсинг новин не використовуються. Іконки станів взято з офіційного сайту ТОЕ.

Тести покривають ізоляцію користувачів, серверні права адміністратора, коди підтвердження, збереження / відновлення підписок, незалежні типи нагадувань, відсутні слоти, нічні інтервали, літній/зимовий час і запобігання повторній відправці. UI пошуку й підтвердження перевірено з тестовим HA адаптером, без реальних push. Збірка контейнера в HA OS і реальна доставка потребують перевірки у вашій системі.

Офіційні джерела: [Ingress і користувачі](https://contributors.home-assistant.io/apps/guides/ingress/), [Core API доступ](https://contributors.home-assistant.io/apps/guides/communication/).
